# AGENTS.md — how an agent works here

You are building Poarta Primară. This repository is the only source of truth: `README.md`
(what and why), `LAW.md` (the rules, `L<n>`), this file (how), `BUILD.md` (what next),
`ARCHITECTURE.md` (the machine), `catalog/` (the row-level law; `catalog/README.md` says which
file to open), `SURFACE.md` (what is still to map).

## Before any code

1. Read `README.md`, `LAW.md`, this file, then the catalog file that owns the articol you will
   touch.
2. Read `BUILD.md`. Take the first work package whose status is `todo` and whose `depends` are
   done.
3. Stop and ask the owner when the WP is a `decision`, when a change touches what L46 reserves
   (sink product, FDB write policy, graph topology, interrupt kinds, watched accounts, any rule
   of `LAW.md`), or when it adds, removes or relaxes a gate (L43). Do not invent the answer.
4. History (done WPs, superseded briefs, the practice harvest) is on branch `pre-tidy` and in git
   log. Read it to trace why something is as it is, or for the detail behind a `SURFACE.md` row;
   it is never a source of rules.

## Operating loop

```
restate the change as: articol_id + poartă open/closed
write or extend a failing test named in the WP
smallest change that passes
uv run pytest -q; uv run ruff check . && uv run ruff format --check .
regenerate SURFACE.md if the catalog, the scenarios or surface/ changed:
  uv run python -m poarta_contabila.surface --write
one WP per commit: mark it done in BUILD.md and remove its details there
```

## Hard bans

- No `Journal.post`, `journal_entries`, `journal_lines`, or a 5-column trial balance as books (L7).
- No INSERT/UPDATE/DELETE on `CONT_BAZA.FDB` (L9, L10).
- No model on a graph edge (L21); a System Two model or a chat agent never chooses the mouth,
  the TVA treatment, or file vs hold (L29).
- No model call outside a role row of `ARTICOLE_MODEL_ROLES_v1.yaml`, or with a model id the row
  does not pin (L28).
- No XML/DBF except through a `WriteModule` row; no `status: active` on any catalog row before
  it is proven in SAGA C and the owner approves (L42).
- No agent Validare (L11).
- No invented SAGA XML tags: extend only from a successful copy-firm import (L19). No guessed
  external format or API: quote the official page in `RESEARCH_LOG.md` (L19).
- No catalog ids invented from Jev output: off-list → HITL `define_articol`.
- No mixed `thread_id` prefixes (L23).
- No client data in the repo (L36); you work only on synthetic tenants and SAGA test firms with
  invented data (L35). Invented CUIs pass `poarta_contabila.types.cui_is_valid`.
- No chat agent, ReAct supervisor, or `chat:` as a poster (L27).
- No D406 generated by this system: SAGA files D406. V2 `file` is not "submitted to ANAF".

## Catalog is executable

- Lane B = YAML in `catalog/`. Lane A = per-client maps and `explained_rules` (in the domain
  store, not in the repo).
- `matches()` first. `|cands| = 1` → skip Jev. `|cands| = 0` or `> 1` → HITL.
- A Job freezes `articol_id`, `schema_version`, `client_type_hash`, `jev_annex_hash`.
- Money and dates in graph state are strings (L24). Decimals live inside compute nodes.
- Resume payloads validate with `extra=forbid` against `ArticoleHITL.resume_schema`.
- Unknown `articol_id` or HITL kind is an error, not a skip.

Do not create `ArticoleJev`, `ArticolePack`, or `ArticoleEmit`. A new catalog row enters as
`status: draft` (L47).

## Tests that must exist before a WriteModule is live

1. Duplicate `source_hash` → the second job does not package.
2. `interrupt` resume → XML written once.
3. `wait_validare` resume without a snapshot → not `acked`.
4. PeriodDiff unexplained → `file` impossible even if Jev says yes.
5. Control `hard_failures > 0` → the WriteModule must not package.
6. A storno job carries `is_storno` and `storno_of`.
7. The module is proven in SAGA C: its copy-firm import succeeded (recorded on the module row).
